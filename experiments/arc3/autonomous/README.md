# ARC3 公開デモ用の自律改善ループ

候補生成 → コード固定 → 公開デモ実行 → 比較 → 採用・棄却 → 次候補、を有限予算で自動実行します。
ユーザー指定により **公式提出は手動** です。この実行器はKaggle Notebookを開始せず、競技提出もしません。

初版の対象は既存の **CPU c8b方策** です。4つの探索パラメータを、観測された失敗頻度と
直前の採否に基づく有限の座標探索で変更します。生成・検証・選択の循環は自動ですが、
任意のアルゴリズムを発明するLLM、GPU方策の自動改変、人間手数の学習済み逆推定器は含みません。
既存のCPU/GPU公式採点サイクルと量子回路workflowは変更していません。

## 自動で行う処理

1. 公式配布ZIPのSHA-256、公開25環境、SDK・評価器・依存バージョンを固定します。
2. 無改変のc8bを同じ条件で測り、比較基準にします。
3. 停滞からの探索開始手数、同じ観測の訪問回数、失敗回避の重み、既存解法を優先する条件から、
   未試行の変更を1つ選びます。失敗頻度が高い場合は失敗回避、それ以外は早期探索を先に試します。
4. 派生Notebookを別ファイルとして固定し、元の公式 `Agent.main()` で各公開ゲームを実行します。
5. SDKのRHAEを選択した全ゲーム・seedで平均します。平均が厳密に改善し、平均クリア数が
   許容範囲を超えて減らなかった候補だけを採用します。同点は採用しません。
6. 採用した候補を次の探索の中心にします。不採用・失敗した候補も保存します。
7. 候補数・時間・改善停止・探索済み近傍の枯渇・STOPファイルのいずれかで終了します。

初期設定は公開25ゲーム、環境seed 0、1ゲーム1200操作（開始RESETを含む）、
基準1版＋新候補最大3版、改善なし3回、全体2時間、1ゲーム6分です。
基準と候補の行動予算は同じで、候補生成側は予算を増やせません。
すべての試行が完了した場合の上限は100ゲーム実行・120,000操作です。
SDKの採点用手数はSDKそのものに従い、開始RESETを含む実際の呼出し回数も別に記録します。

## ローカル実行

リポジトリのルートから、専用のPython環境で実行します。公式配布ZIPは既存のファイルを指定します。

```powershell
python -m pip install -r experiments/arc3/autonomous/requirements.txt
python -B -u experiments/arc3/autonomous/loop.py --official-zip "C:/path/to/arc-prize-2026-arc-agi-3.zip" --out build/autonomous-public
```

`config.json` のコピーを作り、`--config` で指定すると対象の公開ゲーム・seed・有限予算を変更できます。
ゲームを選ぶ場合は `"games": ["ar25", "ft09", "vc33"]` のように指定します。
変更した条件での試行には新しい `--out` を使います。同じパス・同じ条件で再度実行すると再開します。

実行中に出力フォルダー直下へ `STOP` という空ファイルを置けば、現在のゲームが終わった時点で停止します。
終了済みrunは再度実行しても候補を追加しません。コードや依存が変わった状態で既存結果を再利用しません。
予算は最初の開始時刻から計算し、中断や待機を挟んでも回復しません。

完了済みのゲーム結果は候補ID・実験ID・記録ハッシュを照合して再利用します。
実行途中で中断され結果がないゲームは、その候補を不採用として保存し、無断で再実行しません。
基準版が完了しなければ、比較と候補採用を止めます。OSの排他ロックにより同じrunへの二重書込みを防ぎます。

## 成果物と手動提出への引継ぎ

| パス | 内容 |
| --- | --- |
| `protocol.json` | 全条件・コード・データ・依存の固定記録 |
| `state.json` / `report.json` | 候補、採否、現在の採用版、停止理由 |
| `candidates/auto-*/` | 全候補Notebook・manifest・各ゲームの結果 |
| `evaluation/*/scorecard.json` | 公式SDKがローカルで計算した公開ゲーム採点 |
| `evaluation/*/trace.jsonl.gz` | 操作、観測ダイジェスト、進捗の時系列。画面再生用の完全録画ではありません |
| `decisions/` | 各候補の仮説、パラメータ、評価、採否 |
| `selected/submission.ipynb` | この公開デモ試行で選ばれた候補。改善しなければ基準版 |
| `selected/selection.json` | 選定根拠、ハッシュ、範囲、手動提出指定 |

手動で公式評価へ進める場合は、既存 `cycle.py prepare --notebook ...` に選定Notebookを渡し、
その正確な版の接続検査・通常実行を行ってから、既存の手動提出経路を使います。
公開デモ選定だけで公式提出の条件を満たしたことにはしません。

## GitHub Actions

`.github/workflows/arc3-autonomous-public.yml` を追加しています。
push/PRでは制御テストのみを実行します。デフォルトブランチへの反映後、
**ARC3 autonomous public refinement → Run workflow → run_public=true** で有限の公開探索を開始できます。
`workflow_dispatch` はデフォルトブランチ上への定義が必要です。
[GitHub公式説明](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)

公式ZIPの取得にだけ既存の `KAGGLE_API_TOKEN` を使います。探索stepへ認証値を渡さず、
workerは外部ソケット接続を拒否します。これは既知コード用のPython実行制御で、
悪意ある任意コードに対するOSサンドボックスを提供するものではありません。
同じブランチの実行を直列化し、途中の実行を自動キャンセルしません。

中断から再開するときは同じコミット・設定で `source_run_id` を指定します。
artifactの候補と証拠を復元し、配布ZIPを再取得して照合します。環境・Pythonの更新などで
実験IDが変わった場合は停止し、別実験として開始する必要があります。

## 評価範囲

公開デモへの適合を探索する仕組みです。全25本や別seedも未知ゲームの検証にはなりません。
表示する `mean_public_rhae` は **ローカルの公開デモ平均** であり、Kaggle Public Scoreではありません。
繰り返し使う公開セットに対する選択バイアスがあるため、改善が私有評価でも再現する保証はありません。
人間の手数基準は評価器だけが使用し、方策へは画面・状態・クリア数・利用可能操作だけを渡します。
公式SDK 0.9.8の初期スコア登録には最初のfull resetが必要なため、その1回の後にlevel-only resetへ切り替えます。

```powershell
python -B -m unittest discover -s experiments/arc3/autonomous -p test_autonomous.py -v
```

制御テストには合成の採点結果を使います。実ゲームの検証結果と区別して扱います。
